# 交通 OD 调查：视频分段人工计数 + 模型复核

对着路口监控视频做交通量调查时，最麻烦的地方在于数到一半被打断：接了电话回来，不知道刚才数到哪一辆；换成 5 分钟分段之后，又容易漏记、错记，最后和同事的数对不上。

这套工具就干三件事：把长视频切成固定长度的段、让你边看边敲键盘计数、再让本机模型独立数一遍用来复核。

纯本地运行，不联网，数据全部存在浏览器 localStorage 里。

---

## 两个页面

### `video-segmenter.html` — 主工具

视频播放 + 人工计数。双击就能用，不需要装任何东西。

- **分段**：可以在任意位置打一个断点，之后按 5 分钟切段；推进度条随意跳；倍速滑条精确到 0.1（2.6×、3.4× 都行）
- **播满一段自动暂停**，问你要不要接着播下一段，避免一口气跑过头
- **画面放大**：滚轮缩放、拖动平移、框选裁切，远处车道看不清时很实用
- **计数**：右栏顶部一个输入框，边看边敲，敲完按回车记一条

车型编码（敲这些键就行，可以连着敲，比如 `11231231dbc`）：

| 键 | 车型 | 键 | 车型 |
|---|---|---|---|
| `1` | 小客车 | `dbc` | 大巴车 |
| `2` | 出租车 | `dhc` | 大货车 |
| `3` | 摩托车 | `xhc` | 小货车 |
| `gjc` | 公交车 | `5` / `6` | 旧公交车 / 旧大巴 |

另外有一张独立的**新能源表**，不影响原表：`w` 新能源摩托、`s` 燃油摩托、`a` 出租车、`xxhc` 新能源小货车、`xdhc` 新能源大货车、`xdbc` 新能源大巴车、`4` 新能源公交车。没规定的一律算新能源。表里按 `摩托车:50(旧25+新25)` 的格式显示。

其他几个细节：

- **空格键**：输入时按一下就暂停/继续播放，不用去点按钮
- **按段统计**：换段自动归零，上一段的数据还能回看
- **记录明细**：可以逐条删、点行跳转，也能"回到第 N 条"——时间轴和输入框内容一起回退
- **一键复制**：总表 7 列、新能源表 5 列，制表符分隔、不带表头，点完直接粘进 Excel
- **清空前自动留个快照**，误点了还能"撤销清空"
- 区域位置、倍速、识别进度、当前设置都存在本地，换段、刷新都不丢

### `模型监看.html` — 模型复核

模型数出来的数可以直接和人工数对比。这一页是给**调参**用的，画面大、数据实时刷新。

- 左边是模型实时输出（画面上带识别线、检测框和车型标签）
- 右边调识别线和识别区域：线可以直接在画面上拖，区域按住拖一个框，四角能拉伸
- 试算范围可以选起点、时长（15/30/60 秒或全片）、抽帧倍数、推理尺寸
- 实时表按"本段 / 累计"两列显示，过线明细逐条追加，方便对照着找漏检
- 一键复制累计总表或本段数据

这一页的设置存在自己名下（`vseg.mon.settings`），不会动主页面的数据。

## 模型服务

网页里跑不了 PyTorch/CUDA，所以识别交给本机的一个小 HTTP 服务。

```bash
cd server
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
venv\Scripts\python.exe model_server.py 8502
```

首次启动会自动加载 `server/weights/yolov8x.pt`（需自行下载放到该目录），约 20 秒。窗口里出现"就绪"之后，网页右上角会显示"已连接"。

两个页面都会连 `http://127.0.0.1:8502`。想换权重：

```bash
set VEHICLE_WEIGHTS=yolov8m.pt
venv\Scripts\python.exe model_server.py 8502
```

接口：`/health`、`/videos`（列本机目录下的视频）、`/info`、`/still`、`POST /jobs`、`/jobs/<id>/live`、`/jobs/<id>/frame`、`/jobs/<id>/stop`。

`POST /jobs` 支持两种视频来源：`src=` 直接给本机路径（不复制文件），或者把视频二进制作为 body 上传。上传方式产生的临时副本会在任务结束后自动删除。

## 实测数据

RTX 4050 Laptop（6G），1080p 输入，单帧耗时含跟踪开销：

| 权重 | 推理尺寸 | FP32 | FP16 |
|---|---|---|---|
| yolov8x | 640 | 29.1 ms | 17.9 ms |
| yolov8x | 960 | 51.9 ms | 32.5 ms |
| yolov8m | 640 | 12.4 ms | 9.8 ms |
| yolov8m | 960 | 22.8 ms | 15.5 ms |

15 秒片段、抽帧 5×（约 90 帧推理），端到端从 5.6 秒降到 2.8 秒。

## 几个踩过的坑

**抽帧不跳解码。** 一开始以为把抽帧倍数从 3× 调到 5× 就能快 1.6 倍，实测几乎没变化。原因是主循环里 `cap.read()` 对每一帧都在解码，抽帧只是跳过了推理那一半——倍数调得越高，省下来的比例反而越小。改成跳过帧只 `cap.grab()`（1.09 ms/帧）、要处理的那帧才 `retrieve()`（3.27 ms/帧），解码开销砍掉一半多。

**换小模型几乎不提速。** 把 yolov8x 换成 yolov8m，单帧推理从 17.9 ms 降到 9.8 ms，但端到端只快了 18%。因为这时解码占了将近一半，模型再小也降不下来。所以"换个更快的模型"这件事，在抽帧倍数较高时收益很有限。

**画面全黑，两个不同的原因叠在一起。** 一个是 `box.style.display = ''` —— 这行代码只是清掉内联样式，元素会回落到 CSS 里的 `display: none`，盒子永远不显示；另一个是某些嵌入环境的内容安全策略只允许 `img-src 'self' data: blob:`，直接 `<img src="http://127.0.0.1:8502/...">` 会被静默拦截。前者的正解是写 `display: block`，后者改成 `fetch` 取字节再转成 blob 地址。

**框选了却看不见框。** 同样的坑：`#roi` 这条 CSS 里带了 `display: none`，而代码只切 `hidden` 属性，作者样式的优先级压过了它。现象是逻辑明明在跑（松手后坐标确实算出来了），画面上却什么都没有。

**过线判定比检测更容易出错。** 贴着识别线行驶的车，中心点可能始终不越线；被大车挡住几十帧之后轨迹断开，车会重新计数或者直接漏掉。这部分调参占了整个项目后期的大部分时间，所以才有专门做了一页监看。

## 已知限制

- 只有固定的这 7 类车型，COCO 本身没有"面包车"这个类别，面包车会被并入小型客车
- 模型对远处的小车、遮挡严重的车仍有漏检，提高推理尺寸能改善但更慢
- 人工计数存在 localStorage，清理浏览器数据会丢；重要数据请及时用"复制"导出
- Windows 专用（服务端用到了 venv 的 `.exe` 路径约定），网页部分跨平台
